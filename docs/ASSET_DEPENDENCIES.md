# Explicit asset-tool dependency chains

Manifest version 2 adds declared dependency snapshots and private intermediate
outputs to the optional build-time asset pipeline. It uses the same one-shot
literal-argv commands or typed Go transforms as version 1. Normal applications
still need neither an asset manifest nor Node.

```json
{
  "version": 2,
  "tools": [
    {
      "name": "Tokens",
      "command": ["go", "-C", "{project}", "run", "{inputs}/tools/tokens/main.go"],
      "inputs": ["styles/tokens.json", "tools/tokens"],
      "outputs": ["palette.css"],
      "intermediate": true
    },
    {
      "name": "Stylesheet",
      "command": ["go", "-C", "{project}", "run", "{inputs}/tools/styles/main.go"],
      "inputs": ["styles/main.css", "tools/styles"],
      "dependencies": {"tokens": "Tokens"},
      "outputs": ["style.css"]
    }
  ]
}
```

The commands above describe application-owned adapters; the framework does not
supply those executables. A producer verifies every declared output. Its
`intermediate: true` keeps those outputs out of the returned public result,
embedded assets and static-export assets. A consumer sees an independent copy
at `{dependencies}/tokens/palette.css`. Its own `inputs` remain snapshots of
original source declarations. A publishing tool may also be a producer.

`dependencies` maps local aliases to exact declared tool names. Names may retain
spaces. Aliases have 1–64 ASCII characters: an initial letter/digit followed by
letters, digits, dot, underscore or dash. Private/reserved names, case-colliding
aliases, unknown/self dependencies and cycles are rejected before any command
runs. The graph has at most 64 tools, 64 aliases per tool and 256 total edges,
and must contain at least one publishing tool. It runs sequentially in a stable
topological order, retaining manifest order among available independent tools.
A producer can appear after its consumer in the manifest.

Version 2 creates a private dependency directory even for a tool with no
predecessors. Typed transforms use `Workspace.Dependencies()`; executable
adapters using `WorkspaceFromEnv` can call the same method. Commands and their
configured environment can use `{dependencies}`. The reserved environment
variable is `NEXTGO_ASSET_DEPENDENCY_DIR`. The existing three-field Workspace
struct remains unchanged.

Each consumer gets only its explicitly declared aliases. A consumer modifying
its dependency copy does not alter the producer's verified stage, other
consumers or final public files. The pipeline freezes version-2 declarations
after validation so a typed Transform cannot accidentally mutate the caller's
configuration to change later edges, argv or publication rules.

The graph shares a 256 MiB / 10,000-file ledger across framework-created
verified-output, dependency and final-public copies, retaining 64 MiB/file.
Copies count individually, including fanout. A publishing output consumes a
verified copy and a public copy, so graph capacity can be reached before the
ordinary per-file or source-snapshot limits. Source-input snapshots retain their
existing independent limits. Files are read and checked before they are copied.

These bounds cover framework-controlled artifact copying. Tools are trusted
processes/Go code running with user privileges, and can write their own scratch
files or read original project paths; this is not a filesystem sandbox or an OS
disk quota. All intermediate paths still receive the existing secret-file,
symlink, traversal, special-file and reserved-path denial. Private intermediates
are not a secret-storage API.

Only publishing tools contribute to the public path-collision namespace. Two
intermediate producers may both emit `palette.css` because each has an isolated
output directory. Within one producer, duplicate/case/prefix output conflicts
remain invalid. Every publishing output must remain disjoint from every other
publishing output and from source public files.

A producer failure, missing output, consumer failure, timeout or cancellation
aborts and removes the new asset stage. It does not mutate the last successful
application generation or source public directory. Only the successful final
public tree reaches the existing build/export integration. Graph declarations
and every producer's declared source inputs participate in the existing watch
fingerprint. Final generated bytes participate in runtime build identity.

Version 1 keeps independent execution and ordinary publication behavior; it
cannot use nonempty dependencies or intermediates. Its `{dependencies}` text is
not substituted and no dependency directory is created. Duplicate JSON keys now
fail closed in both manifest versions. Older CLIs reject version 2 rather than
silently executing only part of a graph. The added Tool fields require keyed
Tool literals for forward-compatible Go source: unkeyed Tool composites from
older callers need updating. No stable released Go or npm compatibility contract
is asserted by this increment.

This feature does not install Sass/PostCSS/Tailwind, infer their dependency
imports, implement CSS modules, rewrite CSS URLs, generate source maps or provide
stylesheet HMR. Tests use typed Go transforms and fixture executables; they do
not establish compatibility with any selected upstream tool distribution.
Stable public filenames still require suitable native/static-host cache
revalidation. Neither content-addressed public aliases nor static-host response
header publication is added. All 79 parity rows and 11 release gates retain their
existing status; this bounded slice does not complete A03.

## Run the two-stage example

```sh
go run ./cmd/nextgo build --out ./dist/css-pipeline ./examples/css-pipeline
go run ./cmd/nextgo export --out ./dist/css-static ./examples/css-pipeline
```

The actual example first normalizes `styles/tokens.json` into private
`tokens.json`, then reads `{dependencies}/tokens/tokens.json` while rendering
`styles/main.css`. Only the final 564-byte `style.css` is published. The
[example guide](../examples/css-pipeline/README.md) explains stable-filename
revalidation and static-host duties.

Targeted runs on Go 1.27.3 and 1.24.13 Linux ARM64 pass native/WASM/vet checks and
separate real CLI generation, build/export and native execution outside the
source directory. They exercise both actual Go adapters, verify intermediate
outputs are absent from public assets, and preserve the preceding binary and
CSS after an expected invalid-token build failure. These are explicit graph
fixtures, not third-party distribution compatibility. Separately, 128 selected
existing core/location/lazy/stream browser regressions pass per SDK; those are
not CSS-tool conformance tests. Twelve static-host checks also pass per SDK on
the earlier production artifacts. Four separate refresh Node transport checks
per SDK cover native, local buffered/streaming RuntimeAPI and static HTTP/assets,
not WASM instantiation or actual AWS. Later link-readiness unit proofs do not
requalify this production browser/artifact matrix. Development-watch, complete
integration, current budget and remote workflow execution remain pending.
